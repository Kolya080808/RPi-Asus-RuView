# Требования и текущие ограничения

Пользователь: нужен скелет человека с реальным движением, функции RuView,
и скрипт отката всех изменений на устройствах. Pi может быть только веб-сервером.
Pi сейчас в спальне с двумя повторителями; его можно переставить.

Не считать анимированный шаблон, симуляцию или вывод камеры доказательством
восстановления позы по Wi-Fi. Для проверки нужны сопоставленные измерения
CSI и эталонных движений; оценивать также пустую комнату и отключение источника.
Камера разрешена для калибровки/обучения: есть веб-камера и камера телефона.
Предпочтение: всё на Pi Zero 2 W; постоянно работающий ПК нежелателен.
Нужна запись и просмотр истории. Срок хранения/видеозапись не выбраны.

Подтверждено: штатный csimon GT-AX11000 отдаёт записи, 16 за 8 секунд,
без ACK failures/overflow. Рабочая гипотеза: 96 байт заголовка + 224 байта I/Q.
Перенос модели ESP32/MM-Fi на Broadcom не подтверждён.
Второй захват с Pi: 98 полных записей при таймере 100 мс. Область 96:320
повторно подтверждена изменчивостью; хвост имеет два чередующихся хеша.
Драйвер: 99 передач, 1 ACK fail, 0 overflow; сохранено 98 — сбор не без потерь.

RuView README, проверено 2026-09-29: pose_v1 first-cut PCK@20 3.0%;
live cog runtime confidence=0 stub; MM-Fi benchmark — отдельная модель/датасет.
Beta note отдельно указывает ~2.5% по proxy labels, P7–P9 не завершены.
Это заявления upstream, а не наши измерения. Надёжный скелет и полное
соответствие заявленным функциям на ASUS нельзя обещать до валидации.

Перед любыми новыми удалёнными изменениями: сохранить исходное состояние,
записать точные пути/процессы/ключи, расширить rollback.py, проверить откат.
Не устанавливать системы и модели только ради демонстрации без реального
потока. Не перепрошивать основной роутер в рамках диагностики.
