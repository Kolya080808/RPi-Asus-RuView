# Сбор и история на Raspberry Pi

Доступ: ssh pi@192.168.50.100. На Pi:

```sh
python3 /home/pi/ruview-lab/recorder.py capture --seconds 20 --interval-ms 100
python3 /home/pi/ruview-lab/recorder.py history
python3 /home/pi/ruview-lab/recorder.py export SESSION_ID
python3 /home/pi/ruview-lab/motion.py SESSION_ID
```

Сборщик подключается напрямую Pi → ASUS по отдельному ключу. ПК для получения
и сохранения данных не нужен. Python использует только стандартную библиотеку.
Работа ограничена одной сессией 5–60 секунд. После сессии монитор выключается
и временная запись peer удаляется. Сервиса/автозапуска нет.

История: /home/pi/ruview-lab/history.sqlite3. Содержит сырые записи, результат
предварительного декодирования, время начала/окончания сессии, параметры,
полный вывод диагностики и ошибки. Время каждой записи по полю 0x14 ещё
не привязано к UTC; для будущего обучения с камерой нужна синхронизация.
После захвата `recorder.py` автоматически запускает `motion.py`: первые 8 секунд
служат базовой линией, затем устойчивый рост изменения нормализованной амплитуды
записывается как событие в таблицы `motion_samples` и `motion_events`. Это
индикатор движения всей сцены. Он не выдаёт скелет, части тела или пульс.
Видеозаписей и рассчитанных скелетов пока нет. Просмотр сейчас через history
и export; веб-проигрыватель ещё не реализован.

Срок хранения не выбран: автоматического удаления нет. При достижении
базой 256 MiB новые захваты блокируются до ручного архивирования.
Текстовые диагностические логи увеличивают размер; оценивать длительное
хранение по одному только 320-байтовому полезному блоку нельзя.

Проверено 2026-09-29: сессия 40ddd901-0f56-44d4-bebd-0c74c4d6eb04,
10 секунд, 100 мс, 98 записей. Все 2048 байт. Область 96:320 обновляется
в каждом пакете; хвост повторяется A/B. Драйвер насчитал 99 передач,
1 ACK fail, 0 overflow; сборщик пока не гарантирует отсутствие потерь.
Неуспешная попытка сохранена со статусом failed, не выдана за запись.

Профиль декодера ограничен текущим eth6/каналом 4. Другой заголовок не
декодируется молча: исходные байты сохраняются вместе с ошибкой профиля.
Граница динамической области подтверждена дважды; физическая семантика I/Q,
порядок поднесущих и соответствие модели позы остаются гипотезами.

Доступ Pi → ASUS сейчас добавлен в runtime-файл /root/.ssh/authorized_keys;
после перезагрузки ASUS прошивка может пересоздать его из своих настроек.
Постоянные настройки SSH в NVRAM не менялись.
